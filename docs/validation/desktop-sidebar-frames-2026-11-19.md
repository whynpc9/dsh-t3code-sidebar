# Desktop 侧栏渲染性能复测 · 2026-11-19

在官方 DeepSeek Harness Desktop 0.2.2-rc.3（Electron 44.7.0）上，将基线 `7b13b12` 与本次修改交错运行四轮，顺序为候选、基线、基线、候选。菜单打开和关闭、搜索结果、窄栏状态更新、平铺滚动均通过功能检查。平铺切换的收益最大，进入视图时挂载的会话行从 5,001 降至 34。

## 帧间隔与主线程耗时

下表合并各版本两轮样本。帧间隔为相邻 `requestAnimationFrame` 回调时间戳之差，p95 使用最近秩。主线程耗时取 Electron 渲染器 CDP `Performance.getMetrics` 的 `TaskDuration` 整段差值除以动作数，包含宿主界面和测量脚本的工作。单位均为毫秒。

| 场景 | 每版动作数 | 帧间隔 p95 基线 → 候选 | 平均主线程耗时/动作 基线 → 候选 |
| --- | ---: | ---: | ---: |
| 菜单打开或关闭 | 120 | 25.5 → 17.4 | 81.32 → 65.39 |
| 输入搜索词 | 40 | 9.1 → 9.1 | 11.18 → 9.84 |
| 窄栏中交替收起、恢复会话 | 40 | 9.1 → 9.1 | 6.04 → 3.24 |
| 平铺列表中段交替滚动 1 px | 200 | 9.1 → 9.1 | 2.90 → 0.73 |

菜单由点击到下一次 rAF 的 p95 从 **17.2 降至 8.8 ms**。另做一轮直接切换菜单目标，每版各 30 次，旧行关闭、新行打开、弹层可见均通过。切换到下一次 rAF 的 p95 从 18.4 降至 7.9 ms。搜索输入的同一指标从 9.9 降至 8.5 ms。搜索、窄栏更新与微滚动的帧间隔中位数均约 8.3 ms。窄栏的主线程耗时波动较大，两轮基线累计分别约 159、82 ms，两轮候选约 68、62 ms。这里测到的是渲染器回调时序和主线程工作量，未采集 GPU 呈现时间。

## 平铺列表与真实滚动容器

Desktop rc.3 在侧栏外层统一滚动。基线用内层列表的 `clientHeight` 计算窗口，得到 170,048 px，实际可滚动容器高 632 px。候选版用实际滚动容器和列表相对位置计算挂载区间，同一套逻辑也支持列表独立滚动的布局。

从状态视图切换到平铺视图，每版测 8 次，计时从点击菜单项至第二个 rAF 回调，并检查平铺 DOM 已挂载。基线为 **777.2–914.8 ms**，候选为 **10.3–16.2 ms**，中位数分别为 796.6 和 12.8 ms。基线每次挂载 5,001 行，候选每次挂载 34 行。

微滚动直接操作真实共享容器，交替使用 84,788 和 84,789 px。候选两轮的最初两次采样为 59 行，随后 98 次稳定在相同的 60 行窗口。另行验证了顶部、中点和末尾均有可见会话，Home、End 分别聚焦第 1、5,001 行，定位当前会话后焦点正确返回选中行。

## 环境与操作

- Apple M4 Max、macOS 26.6.2（25G83）、1280 × 820 Desktop 窗口。每轮使用独立 DSH_HOME 和 Electron 用户目录，同一份种子目录克隆出 100 个工作区，每组 50 条已完成的合成会话。使用规范路径生成工作区和会话日志，真实宿主另有一条当前空白会话。
- 通过本机 CDP 驱动 Desktop 渲染器。菜单场景展开全部 100 组，保留每组默认的显示数量，检查 500 个有菜单的会话行。每轮在两个会话间交替选择目标，共打开、关闭各 30 次，分别检查按钮状态和菜单弹层。
- 搜索场景交替输入工作区名 `w000`、`w001`，每次均显示 20 条本地匹配结果，输入间隔短于正文检索防抖期。窄栏场景通过真实 Host 接口交替执行 Settle、Reopen，检查 20 个连续 revision 以及侧栏保持窄栏、会话行数为零。
- 两版共用依赖与构建设置。四轮都核对了独立 profile 中安装的 client bundle SHA-256。逐帧样本、逐动作耗时、每轮主线程计数与导航结果见[测量数据](desktop-sidebar-frames-2026-11-19.json)。

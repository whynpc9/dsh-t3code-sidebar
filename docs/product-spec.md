# DeepSeek Harness T3 Sidebar 产品规格

版本：Draft 0.1 · 2026-11-08。本文中的“必须”是 v0.1 发布要求；“后续”有明确阶段，不属于首版完成承诺。

## 1. 产品目标与已确认要求

用户需要一个 DeepSeek Harness 插件，使其具备 T3 Code 风格 Sidebar。已确认两种视图都要，并可切换；任务分区视图优先、默认开启、先开发和验收。项目视图仍在 v0.1 范围内。

核心价值是让使用者同时管理多个 agent 会话：知道什么正在运行、什么需要处理、什么暂时搁置、什么已经处理，再快速返回对应聊天。沿用 Harness 对 Session 和 Workspace 的定义，不把普通文件夹强制认定为 Git 仓库。

参照固定版本的 [T3 Code 源码调研](research/t3-code-source-review.md)。当前 T3 的 Attention 主要是状态与返回 Active 的规则，并非单独分区；其 Boring 模式也不是完整的传统项目树。这里采用五分区任务视图，并自行定义完整的项目视图。借鉴行为与信息结构，不要求像素级复制品牌、图标或全部外围功能。

## 2. 首版范围

| 编号 | v0.1 必须支持 | 验收重点 |
| --- | --- | --- |
| F01 | 默认任务视图，切换项目视图，记住选择 | 切换不改变当前会话、草稿或任务状态 |
| F02 | Pinned / Active / Working / Snoozed / Settled 五分区 | 一个会话只有一个主位置；优先规则确定 |
| F03 | 运行、子任务运行、待审批、待输入、失败、未读结果 | 未知或断线不伪装为空闲或已处理 |
| F04 | Snooze、恢复、到时返回、新关注事件提前返回 | 浏览器关闭/Host 重启后语义仍成立 |
| F05 | 手动与按不活跃窗口自动标为已处理、重新打开、新事件返回 | Settled 不归档，不停止任务；自动规则可关闭和按项目覆盖 |
| F06 | Harness 原生置顶/取消置顶、打开、创建、重命名、归档/恢复 | 与原生界面读回一致；归档运行任务遵从原生拒绝/确认 |
| F07 | 项目筛选、会话标题搜索、按需内容搜索 | 搜索结果完整说明范围和截断，不打开所有历史 |
| F08 | 项目视图：Workspace 折叠、会话列表、未分组、项目管理 | 路径身份由 Host 判定；空项目可新建会话 |
| F09 | 当前项可发现、键盘操作、无障碍、窄屏和主题 | 折叠/筛选后仍能定位当前会话 |
| F10 | 安装、停用、卸载和故障回退 | 停用恢复原生区域；聊天记录与原生配置保持可用 |
| F11 | 时间策略设置、继承/会话豁免、到期计算、恢复补算、迁移原因 | 首版自动 Settled + Snooze；精确规则见[时间策略 Spec](time-policy-spec.md) |

后续 v0.2：跨分区拖拽、置顶排序、批量操作、Working 关闭后的手动 Active 排序、更多快捷键；自动归档候选/策略也进入计划，但自动执行须通过原生归档原子保护验证。后续 v0.3：PR 关闭/合并触发 Settled 与保留 PR 会话、Git/分支/PR/worktree 装饰、更多远程身份场景、经验证的第三方 row 扩展适配。所有时间规则统一见[时间策略 Spec](time-policy-spec.md)，自动 Settled 不再延至 v0.2。

首版不创建或删除 Git worktree，不管理 agent/provider/model，不复制聊天窗口，不实现永久删除会话，不把 Snooze 变成定时发消息或执行命令。多 Host 聚合、团队共享任务状态、跨机器同步个人阅读状态均不在首版内。

## 3. 信息结构

任务视图默认布局如下。顶部品牌、新会话入口和底部设置由 Harness 外壳保留；本插件只拥有框内浏览区域。

```text
┌ Harness 外壳：品牌 / New Session ──────────┐
│ [任务 ▾]   [全部项目 ▾]          [搜索]  │
│                                         │
│ ▾ 置顶 Pinned                       2  │
│   ● 修复导出字体       项目 A    待审批   │
│   ○ 下一阶段规划       项目 B           │
│ ▾ 待处理 Active                     3  │
│   ! 构建失败           项目 A    失败     │
│   ● 校验结果           项目 B    新结果   │
│   ○ 整理需求           未分组           │
│ ▸ 运行中 Working                    4  │
│ ▸ 稍后处理 Snoozed                  2  │
│ ▸ 已处理 Settled                   18  │
│ [查看归档]                              │
└ Harness 外壳：设置 / 其他插件入口 ────────┘
```

Pinned、Active 默认展开，Working、Snoozed、Settled 默认折叠。标题计数为当前项目范围内、搜索过滤后的逻辑会话数；可见行数与总数分开，计数不因分页或折叠改变。归档是独立过滤入口，不算第六种任务状态。

行主文案为标题；无标题使用本地化“未命名”。副文案在任务视图显示项目名，重名时附最短可区分路径尾部，完整路径放在 tooltip。状态图标必须同时有文字或无障碍标签。运行、关注、选择、未读分别表达，不复用一个颜色承担全部含义。

## 4. 分区和任务语义

### 4.1 状态来源

运行、审批、输入请求、原生置顶与归档属于 Harness。Snooze、手动/自动 Settled、任务排序属于插件。阅读标记属于当前浏览器用户界面，不应把浏览器重新打开误判为发生了一条新的任务事件。公开状态不足时，由插件 Host 端补充摘要和可比较的事件游标，不能靠扫描 DOM 或每行打开完整聊天补齐。

### 4.2 分区优先规则

按顺序计算，并由两种视图共用同一个纯函数：

1. Host 未授权、已删除、子 agent 独立记录不进入顶层任务列表；空白新会话仅在当前选中时显示。
2. 归档会话进入归档结果，排除于五分区。已知元数据先保留，恢复时重新计算。
3. 原生置顶会话进入 Pinned；行内仍显示审批、运行或失败，不在其他分区重复出现。
4. 有效 Snooze 进入 Snoozed，除非已到期或出现符合规则的新关注事件。
5. 有效手动或自动 Settled 进入 Settled，除非出现用户新输入、开始新一轮运行或新关注事件。
6. 无待处理关注事件且有正在执行的会话/子任务，进入 Working。
7. 其余进入 Active。Active 可以有暂时空闲但未标记已处理的会话。

后台定时任务“已配置”只显示时钟装饰，不等于正在运行。运行状态未知时保留最后可信位置并标记“状态待同步”，不自动进入 Settled。错误、取消、成功必须区分；普通工具调用失败但 agent 继续运行时，不直接宣告整个任务失败。

### 4.3 Snooze

- 选项：1 小时、3 小时、今天 18 点、明天上午 9 点、下周一上午 9 点、自定义时间；以操作时的用户时区转换成绝对 UTC 毫秒，显示完整唤醒时间。Host 时间是到期判断权威，夏令时歧义需确认实际日期时间。
- Snooze 不暂停、取消或停止 agent，只延迟在待处理区显示。对话框需用一句话说明这一点。
- 可暂缓已有普通输入问题和已存在的失败；新出现的输入问题、失败、审批或受支持的子任务请求提前唤醒。为避免隐藏权限操作，**首版不允许将尚未解决的审批任务 Snooze 或标为 Settled**。这是本插件明确的产品约束。
- 普通成功完成和无关注事件的后台运行不提前唤醒；到期后进入 Active 或 Working，取决于当时真实状态。
- Snooze 命令作用于置顶会话前提示先取消置顶；首版不做跨原生置顶和插件元数据的隐式双写。
- 手动“立即返回”清除 Snooze。过期任务在进程恢复时补算；同一任务同一唤醒事件只能生效一次。

### 4.4 Settled

中文显示“已处理”，避免暗示 agent 已成功完成用户目标。支持手动标记，以及按配置的不活跃窗口自动标记；后者必须通过全部保护条件，不能仅因 `running=false` 或已读就标记。默认时间预设为 7 天，范围 1–90 整天，允许关闭；已有历史的启用宽限、唤醒宽限和单会话禁用见[时间策略 Spec](time-policy-spec.md)。

运行中、存在运行子任务、待审批/输入、状态未知时不可标为已处理。错误任务可以在确认已知失败后手动标记已处理，保留失败标记；自动规则默认允许已结束的旧结果在超期后收起，可配置保留未确认失败/结果。置顶会话须先取消置顶。新输入、新运行或新关注事件使其重新进入 Active/Working。归档另走原生命令。手动重新打开提供“在下次新活动前不自动收起”的保护，避免立即被定时扫描再次收起。

首版置顶只覆盖停车状态的展示，不隐式清除 Snooze/Settled 元数据；取消置顶后按当时是否到期/是否有新事件重新计算。此规则有意避免原生 pin 与插件存储之间不可原子提交的双写，区别于 T3 的 Pin 清停车行为。界面在置顶操作后提示保留的稍后处理状态。自动 Settled 始终跳过置顶。

### 4.5 排序与稳定性

首版 Pinned 使用原生置顶集合的稳定顺序（若 Host 集合不承诺顺序，以插件稳定排序补齐，不把集合顺序冒充契约）；Active 按“需要关注的返回事件”时间倒序，再按最近用户活动、稳定会话 ID 排序；Working 按本轮开始时间倒序；Snoozed 按唤醒时间升序；Settled 按标记时间倒序。所有排序都禁止由 token chunk 更新时间驱动。

仅开始/结束/新关注等语义变化触发跨区移动。菜单打开、键盘聚焦或拖拽时暂缓视觉重排；命令仍针对捕获的 Session ID，结束交互后应用新位置。当前选中行迁移时保持聊天选择，给出短暂位置提示。

## 5. 双视图和项目筛选

任务视图默认展示全部项目；项目筛选影响全部五分区和搜索。新建会话优先使用显式项目，再使用 Harness 的当前/最近项目规则；“全部项目”不是可创建会话的工作目录。

项目视图按 Workspace 分组，组内优先置顶，再关注、运行、普通 Active；Snoozed/Settled 用折叠子分组显示，归档仍独立。显示未分组区，支持空项目、新建会话、重命名项目；删除项目继续使用 Host 原生语义和确认，不等于删除目录或任务历史。

切换视图只修改展示偏好，保留搜索词、项目范围、当前选择、草稿、metadata。每种视图保存独立折叠状态和滚动锚点。当前会话若被项目筛选/搜索排除，顶部显示“当前会话不在此范围 · 定位”，点击后清除冲突过滤并展开、滚动到该行；不偷偷把不匹配项塞入结果计数。

折叠分区可保留当前会话的唯一预览行。分页的当前项应临时展开到可见范围。子 agent 会话不重复作为普通根任务；父行可显示子任务数量与状态，继续使用 Harness 原有子任务导航。

## 6. 搜索和会话操作

标题/项目名本地即时过滤；内容搜索显式进入搜索模式，调用原生 `sessions.search`，200 ms 防抖，取消旧请求且以 query generation 拒收迟到结果。正文命中不改变权威会话列表、排序、分区状态。界面明确“仅标题/项目”或“包含正文”；受限条数/hasMore 必须展示，不伪装完整搜索。

右键和更多菜单：打开、置顶、Snooze/立即返回、已处理/重新打开、重命名、复制会话 ID、归档/恢复。原生结构化菜单可复用；插件动作通过自己的注册追加。首版 fork 为尽力复用原生可用菜单，不承诺新建 worktree。

命令进行中只禁用同一资源上冲突的动作，失败恢复原值并提示原因。归档运行任务时，展示 Host 返回的运行活动，并按原生流程允许取消或明确停止并归档；不能把“归档”直接重写成强制停止。

## 7. 外观、键盘与无障碍

使用 Harness 公共 primitives、locale 和样式 token，避免硬编码品牌 CSS。支持中文/英文、浅色/深色、200% 缩放、长标题、中英文混排。侧栏宽度/折叠由 Harness 外壳拥有；首版不修改外壳拖动宽度逻辑。

键盘：Tab 可遍历所有操作；列表内上下移动、Home/End、Enter 打开、左右折叠展开，Escape 退出菜单/搜索。搜索快捷键优先复用宿主目录，不强占编辑器输入键。上下文菜单有键盘入口，所有 hover-only 操作有可聚焦替代。新快捷键通过 Harness shortcuts 服务注册并在停用时注销。

容器采用分组列表语义，项目树使用与实际层级一致的 tree 语义；`aria-expanded`、`aria-current`、状态读屏文本与视觉一致。更新数量用节流后的 live region 宣读，运行 token 不反复播报。尊重 reduced-motion，窄屏复用宿主展开/覆盖行为。

## 8. 验收场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 首装及切换视图 | 默认任务；项目切换后返回同一会话，草稿保留，刷新记住视图 |
| A02 | 运行 → 等审批 → 继续 → 完成 | Working → Active（审批）→ Working → Active（新结果）；置顶时保持 Pinned 并改变状态 |
| A03 | Snooze 后旧问题重复推送/新问题出现 | 旧问题不唤醒；新 ID/代次的问题唤醒一次；新审批一定可发现 |
| A04 | Snooze 中完成、跨浏览器关闭和 Host 重启 | 普通完成不提前返回；到时/恢复后计算正确 |
| A05 | Settled 后重新发消息/开始新任务 | 重新 Active/Working；不会自动恢复归档，也不残留重复行 |
| A06 | 并发点击、多标签与掉线重试 | 无丢失更新、重复命令或错误回滚；冲突可见 |
| A07 | 搜索 A 慢响应晚于搜索 B | 最终只显示 B；命中/计数/归档范围一致 |
| A08 | 折叠、过滤和排序变化 | 当前项可定位，键盘焦点不丢，正在操作的菜单不跳行 |
| A09 | 原生窗口/原生菜单修改置顶或归档 | 插件即时或重连后收敛到同一状态 |
| A10 | 权限撤回、未知字段、插件 API 不可用 | 不展示越权数据，不执行命令，不把未知状态判为完成 |
| A11 | 停用/卸载/加载失败 | 原生 Sidebar 可恢复，Session 继续运行，记录仍能打开 |
| A12 | 规模与可访问性 | 满足实现 Spec 的性能预算和键盘/读屏检查 |

所有场景都需有自动化证据；A01/A02/A08/A11/A12 还需 GUI 人工式验收。本文是验收要求，不表示任何场景已经通过。

# DeepSeek Harness 外部侧栏插件边界

依据上游 [`fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`](https://github.com/deepseek-ai/deepseek-harness/commit/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159) 的公开源码和文档，版本为 `0.2.2-rc.1`。本次仅做静态核对，未构建插件、启动应用或执行 GUI 验证。以下区分源码行为与项目设计。

## 可替换的范围

- 保留 `ui-sidebar` 和 `ui-workspace`，由插件在 `sidebar.workspaces` 注册一个根级组件即可替换会话浏览区。外层仍负责品牌、全局新会话、侧栏折叠、面板与设置。槽是 `single/root`。原浏览器省略 `priority`，默认 0，**数值更小的注册获胜**。例如普通安装型插件可用 `-1`。同一个槽同一优先级会抛错，异值共存并仅渲染当前赢家。使用 `ctx.slots.inject(key, () => ctx.slots.register(...))`，等待声明并跟随声明生命周期。 [外层注册](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-sidebar/src/client/index.ts#L93-L106) · [原浏览器注册](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-workspace/src/client/index.ts#L318-L335) · [槽核心](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-slots/src/index.ts#L1160-L1189) · [渲染选择](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-renderer/src/client/scoped-slots.tsx#L1341-L1345)
- 原注册虽然被遮盖，仍留在 ledger。子槽在注册时立即取得声明，键在 SlotCore 内只有一个声明者；复制同名 children 会抛错，与加载顺序和哪个组件正在渲染无关。渲染权限也绑定登记项的 children，因此新组件不能靠原子槽仍存在就渲染它们。受影响的是目录流、hover archive/pin、session row leading/trailing/hover 等；Session 菜单扩展位由独立的 `contextMenu.content` 登记声明，可继续通过 host 菜单使用。 [声明与释放](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-slots/src/index.ts#L1280-L1351) · [子槽渲染授权](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-renderer/src/client/scoped-slots.tsx#L65-L88) · [原子槽及菜单登记](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-workspace/src/client/index.ts#L318-L347)
- `WorkspaceBrowser`、`browserInjected` 和原 view store 属于内置实现。包的 `./client` 导出 `WorkspaceBrowserInjected`、`WorkspaceBrowserProps` 等**类型**。渲染器只组装当前注册的 store 和业务注入，外加共享的槽注入、owner props 和标准 hooks。可使用外层给胜者的 `useSectionScroller`，并遵循外层的视口与滚动交接契约。 [公开类型与内部组件](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-workspace/src/client/index.ts#L49-L79) · [原业务注入](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-workspace/src/client/index.ts#L290-L335) · [装配](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-renderer/src/client/scoped-slots.tsx#L611-L671) · [滚动契约](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-sidebar/README.md#L83-L89)
- 建议两个视图共用一个替换注册，默认任务分区，可切换插件自己的项目分组视图，避免切换时重新竞争槽和清理资源。若“项目视图”要求原生 UI，源码可支持撤销覆盖以恢复原组件，但该处的插件切换按钮会随覆盖卸载。可恢复双向切换需要独立的持久入口和额外 PoC；无法把原组件当作同一个外部组件内的子视图公开复用。
- 可复用 `ctx.uiWorkspace` 的导航、会话新建/复用、fork、归档恢复、置顶、目录方法及权限订阅。保留 `ui-workspace` 的 global hooks、独立 context menu、会话重命名/归档确认及提示浮层。新行可以通过 `ctx.contextMenus.open` 传 `{ kind: "session", value: { sessionId, displayTitle } }`，复用内置菜单动作。内置置顶还会维护原视图保存的顺序，插件自己的排序必须依据 Host 置顶状态另行投影。原目录选择器的 sidebar 渲染流和 `session.search`、`workspace.add` 快捷键依赖原浏览器消费内部控件，覆盖后即使快捷键仍注册也不能视为已迁移；workspace rename/delete 菜单也写入原浏览器所读的请求。需要插件自己的可访问入口，并在 PoC 中验证快捷键和目录能力的衔接。 [UiWorkspace 服务](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-workspace/src/client/navigation.ts#L39-L152) · [ContextMenus](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-context-menu/src/client/types.ts#L118-L150) · [原 workspace 动作与浏览器注入](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-workspace/src/client/index.ts#L268-L313) · [会话浮层](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-workspace/src/client/index.ts#L336-L364) · [快捷键](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-workspace/src/client/shortcuts.ts#L65-L117)

## 独立包构建和安装

1. 使用普通 npm/Cordis bundle。包根为可加载的 Host 入口，可采用空 `apply`，由 `dsh.bundle.patch` 指向随包发布的 `cordis.patch.yml`。patch 用稳定的唯一 entry id 插入指向裸包名的一行。补齐 `exports["."]`、`exports["./client"]`、发布文件清单以及 `dsh.client.platform: "web"`。浏览器半部挂在包根 Loader 行，勿把它放在 subpath 行。 `dsh.client.inject` 是浏览器图中的包名依赖，不保证 Cordis apply 顺序；客户端自己的 `inject` 声明所需服务，并通过 `slots.inject` 等待槽。 [公开发布指南](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/user/develop/basic/publish.md#L26-L66) · [浏览器入口指南](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/cookbook/adding-a-settings-card.md#L56-L72) · [图扫描](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/subsystems/client-modules.md#L92-L100) · [上游等候方式](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-workspace/src/client/index.ts#L95-L105)
2. `./client` 是通过 `window.__ModuleLoader__.load({ id, factory(require) })` 登记的 lazy CJS 脚本，id 使用 npm 包名。仓库的 `clientBundle` tsdown preset **未作为公共包发布**。外部项目要实现这一产物格式，可先按公开 fixture 产出最小单文件，再为 TSX/CSS 配置自己的编译封装。浏览器静态 baseline 提供 React、Cordis 等共享实例，保留为外部请求，类型导入编译掉。额外运行时请求按精确标识符列入 `dsh.client.external`，且必须有图行或准确的静态表键供给。Node 的 npm peer 解析和浏览器 module-table external 分开配置；需要共用宿主实例的 DSH 依赖放入 `peerDependencies` 和用于类型检查的 `devDependencies`。用经验证的 `engines.dsh` 版本范围表达兼容性，缺少它时安装和启动会回看 DSH peer 范围。 [未发布 preset](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/cookbook/adding-a-settings-card.md#L56-L69) · [官方封装实现](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/tsdown.client.ts#L924-L943) · [已安装外部 fixture](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/web/tests/fixtures/plugins/fixture-live-client/client.js#L1-L17) · [共享模块](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/modules/README.md#L32-L60) · [版本和 peers](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/user/develop/basic/publish.md#L64-L107)
3. Web 在新建隔离 profile 中从 `web` 模板初始化，再用 `dsh plugin --profile <profile> add <spec>` 安装本地构建目录、tarball 或 registry 包，先用 `--dump-config` 检查实际组合。官方示例演示相对目录，插件管理器也处理 Git 和 tarball。Git `prepare` 可能被 pnpm 脚本政策阻断，本地预构建 tarball 有利于验证发布内容。 `--from-default-profile` 会替换整个目标 profile，仅用于新建的测试名。npm 或 Git 市场索引需要 `dsh.bundle`，无需依赖市场才能安装。 [CLI profile](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/cli/reference/README.md#L13-L24) · [dump](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/cli/reference/README.md#L45-L60) · [安装与移除](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/user/develop/basic/publish.md#L77-L118) · [包管理限制](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/boot/plugin-manager/README.md#L72-L79) · [市场发现](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/user/guide/plugin-market.md#L87-L100)
4. `cordis-client-runner` 是另一种沙箱执行通道，面向宿主动态分发的浏览器半部，使用受限 plain JS 环境。它对非 chain 注册自动覆写 priority，从 0 向负数递减。普通外部 npm bundle 应按上述 Loader/模块图协议显式声明 priority。两条通道都可能占用同一位置，PoC 若有其他替换插件应检查真实赢家与相同 priority 冲突。 [动态 runner 限制](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/extensions/cordis-client-runner/README.md#L28-L54) · [自动 priority](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/extensions/cordis-client-runner/src/client/guard.ts#L125-L139) · [计数初值](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/extensions/cordis-client-runner/src/client/runtime.ts#L178-L185) · [分配](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/extensions/cordis-client-runner/src/client/runtime.ts#L418-L427)

## 生命周期、平台及 PoC

- 单实例是每个运行中的页面、每个 root 槽只渲染一个胜者，不能拿来实现跨标签页或跨进程的单例。使用唯一包名、唯一 profile 行，React 本地状态或插件自有 store，所有注册、事件和异步订阅随 Cordis fiber 或 React effect 释放。模块图拒绝不同活动来源解析到同一包名。槽 disposer 会移除覆盖并重新选出仍在 ledger 的内置注册；移除自有 children 只递归清除自己的槽。Web HMR 负责客户端增删和资源清理；上游外部 fixture 覆盖过安装行、移除和异步清理，但此项目尚未验证 sidebar 赢家恢复、重建重入和崩溃降级。 [槽释放](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-slots/src/index.ts#L1346-L1351) · [图与 HMR](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/subsystems/client-modules.md#L90-L100) · [图同步](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/subsystems/client-modules.md#L122-L124) · [上游清理场景](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/web/tests/client-plugin-live.e2e.ts#L409-L433)
- Desktop 是同一 Web UI 的 Electron 封装，普通 `web` 客户端产物可作为候选，不需写 Electron UI 或 IPC。Desktop profile 的外部包与 npm CLI 的 Web profile 独立。官方支持通过应用内插件管理页，或在应用初始化并完全退出后，用 **Desktop 安装的 CLI** `dsh plugin --profile desktop add <spec>` / `remove <pkg>`，然后重新打开。Desktop 安装/HMR 不能从 Web 测试直接推定。目录能力由 Host 决定，本机 chooser 与远程浏览模式有不同 provider。 [Electron 共享 UI](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/desktop/README.md#L36-L40) · [Desktop 管理流程](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/desktop/README.md#L130-L150) · [应用内插件管理](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/desktop/README.md#L166-L178) · [目录 chooser 限制](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-directory-picker-native/README.md#L28-L34)
- 第一轮 PoC 应分别在独立 Web profile 和 Desktop 测试环境安装同一预构建 tarball，记录运行时精确版本。检查首屏仅有一个替换区、默认任务分区和项目视图切换、原设置与全局新会话、权限和导航、菜单的 Session 目标、搜索与添加目录快捷键、原生 chooser/远程浏览、有无目录能力三类环境、折叠/窄屏滚动。覆盖启用、disable、重启与卸载后回到内置侧栏，重复 enable / rebuild 后无重复 DOM、订阅或样式。再验证外部包失败时宿主错误与回退、同槽竞争以及 profile 之间的隔离。

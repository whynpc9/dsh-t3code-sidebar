## 序号与冷启动

## 插件状态和权限

- 以自有 storage domain 保存每会话的 `snoozedUntil`、显式 settle/ack 基线、版本以及适用的 session 身份证据。建议首次实现采用唯一 domain（例如 `t3_sidebar`）和单个小型 session 表，使用 `defineDomain/domainTable`、`ctx.storageDomain.open`及 `close`，成功落盘才发布。`table.update` 仅能原子修改既有记录，缺键会拒绝。首次写入的 revision 校验与 upsert 需由插件在同一 Host 命令队列中串行执行。Host 的 pin 与 workspace 顺序保留各自权威，工作区/任务视图均从公开快照派生，`active`/`working` 分段优先级是产品规则。将有效 snooze、显式 settle 与 turn 指标分开，避免仅因无运行或无提醒就落盘 settle。[公开 storage domain](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/storage/storage-domain/src/index.ts#L85-L119) · [串行修改和关闭](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/storage/storage-domain/src/domain.ts#L95-L137)

## 重连、停用和验证项

- Session 控制器跟随 connection generation，重建 control 并重新拉目录。公开 `list.phase` 在首次成功后保持 ready，不能用它判定新一代目录已完成。Workspace follow 提供自己的 baseline。插件记录当前 generation，先标旧数据为 stale/只读，用新 baseline 原子替换本地副本，再接受当前代增量。初始化、重连与重新启用都不要从旧快照差异制造完成/唤醒；可靠的新事件与上一次持久确认比较需要同源、可比较的 token。若实现插件 follow，每代发恰好一个完整 baseline，增量有 revision，断档就重新 baseline。插件服务关闭先撤订阅与入口，再 drain storage；重新启用加载自有持久记录并重新计算到期状态。[Session generation](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/api/session-controller/src/client/index.ts#L112-L148) · [目录 phase 的语义](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/api/session-controller/src/client/sessions/manager.ts#L34-L42) · [Workspace baseline](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/api/workspace-controller/src/client/index.ts#L85-L121) · [Gateway snapshot stream](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/api/gateway/src/client/snapshot-stream.ts#L11-L90)
- PoC 一。目标发行版安装独立 Host/Client 包，确认生成 Remote、namespace mount、owner 调用和 guest 拒绝，卸载后旧方法句柄失效。
- PoC 二。两个 owner 窗口以相同旧 revision 争用同会话状态，验证冲突、断线落盘后重试、重启 baseline 和 disable/enable。
- PoC 三。未打开根/直接子会话下验证 permission、定时 ask open/continued/answer 与活动结束；覆盖未挂载发布器、连接中断、无缓存或旧 checkpoint、错误 turn、正常完成、手工中止、fork 和恢复修复。记录可证明的 warm/cold/首次安装读成本及缺项率，再决定是否引入自定义 journal 投影。
